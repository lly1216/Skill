# 四足运控算法与安全门禁

四足运控的全部工作可以压成一条链路：**想要的机体运动 → 足端轨迹 → 关节角/速度/力矩 → 电机**。
下面每一节都按"输入 / 输出 / 数据来源 / 如何变成关节量 / 控制周期 / 真机风险"来写。频率与数值是**默认安全值**，不是厂家规格；
真实机器人以 `待核实`（厂家 SDK 文档、电机手册、`ros2 topic list` 实测频率）为准。

## 是什么与为什么

### 1. 坐标系与姿态表示（一切算法的地基）

- **世界坐标系（world / odom frame）**：不随机器人运动，用于表达路径、重心轨迹、地形高度。来源：里程计/定位节点（见 06 文件的 TF 与 SLAM 链路）。
- **机体坐标系（body / base_link frame）**：原点在躯干几何中心或 IMU 安装点，x 前、y 左、z 上（ROS 约定右手系）。来源：URDF 定义 + TF 发布。
- **关节坐标系（joint frame）**：每个关节一个，随电机转动。来源：URDF 的 `origin`/`axis`。
- 三者由 **TF 树**串起来：`world → odom → base_link → hip → thigh → shin → foot`。任何"我以为在机体系的向量其实是世界系"的 bug，都会表现为机器人朝反方向走或直接摔倒，所以运控节点启动时必须先校验 TF 链通。

- **旋转矩阵（rotation matrix）** R：3×3 正交矩阵，`R_body_world` 把机体向量转到世界系。优点：无奇异、可直接矩阵乘法；缺点：9 个数但有 6 个约束，无法直接插值（线性插值后会失去正交性，必须重新正交化）。
- **欧拉角（Euler angles）**：roll/pitch/yaw，人机交互和 PID 调参时的可读表示。缺点：万向锁（gimbal lock，pitch=±90° 时 roll 与 yaw 耦合），且 yaw 在多圈后不连续（需 unwrap）。**只用于显示与调参，不要用于姿态积分或插值。**
- **四元数（quaternion）**：4 个数，无奇异，姿态积分与插值（SLERP）首选。必须单位化（每次积分后 normalize），否则姿态会漂。姿态来源：IMU 的陀螺仪积分（高频、会漂）+ 加速度计/磁力计修正（低频、易受运动加速度干扰）。
- 工程惯例：节点内部统一用四元数/旋转矩阵计算，只在日志、可视化、参数接口上转成欧拉角。转换顺序固定为 `ZYX`（yaw-pitch-roll）并写进文档，否则与 ROS 的 `tf2`、仿真、同事的代码各说各话。

### 2. 运动学：FK / IK / Jacobian

- **正运动学（Forward Kinematics, FK）**：输入关节角 `q`，输出足端在机体系的位姿 `p = f(q)`。数据来源：URDF 关节链 + 编码器读回的关节角。用途：算足端实际位置、做接触检测、做 IK 的初值。周期：与主控同频（200–500 Hz）即可，代价极低。
- **逆运动学（Inverse Kinematics, IK）**：输入期望足端位置 `p_des`（由步态/身体姿态控制器给出）与机体姿态，输出期望关节角 `q_des`。单腿 3 自由度常用解析解（髋偏航 + 两连杆），也可用数值迭代解（雅可比伪逆/DLS）。输出直接就是位置控制的给定值。
- **Jacobian（雅可比矩阵）** J：`v_foot = J(q)·q̇` 与 `τ = Jᵀ·F_foot`。是"足端速度/力 ↔ 关节速度/力矩"的翻译器。用于：笛卡尔阻抗控制、力控、奇异点检测（`det(J)` 或条件数变大意味着接近奇异，此处关节速度会爆掉，必须提前降速或回避）。
- **控制周期怎么定**：按最内层闭环带宽反推。电流环/力矩环通常由电机驱动器内部完成（约 1–10 kHz，`待核实`）；位置/速度指令从主控经总线周期下发，**建议 500 Hz–1 kHz（2 ms 周期）**，因为 1 kHz 下 10 ms 通信抖动只占 1%，而 100 Hz 下同样抖动会直接让阻抗控制发散。步态与足端轨迹层 50–200 Hz 足够（足端速度变化是慢变量）。决策：**内层快、外层慢**，用时间戳而非"数消息条数"来对齐。

### 3. 动力学基础与 Whole Body Control / MPC / RL

- **动力学（dynamics）**：`M(q)q̈ + C(q,q̇)q̇ + G(q) = τ + JᵀF_ext`。惯性矩阵 M、科氏/离心项 C、重力项 G。四足的真实难点在**接触**：足端接触力 `F_ext` 与地面约束使方程分段不连续。数据来源：URDF 的质量/惯量参数 + 关节编码器 + IMU + 足端力传感器。工程上不必自己推导：用成熟库（如 Pinocchio、Drake 一类，具体版本 `待核实`）算 M/C/G，但必须理解 G 是"重力前馈"、这是让腿"不掉"的最小补偿项。
- **Whole Body Control（WBC，全身控制）**：输入期望任务（躯干位姿、足端位置、接触力、姿态），输出 全部关节的力矩/位置指令。做法是把多个任务写成带优先级的二次规划（QP）：硬约束（关节限位、力矩上限、摩擦锥）优先，软任务按权重排。数据来源：状态估计 + 规划层。周期：200–500 Hz。真机风险：QP 不可解时必须**有降级路径**（丢低优先级任务 → 锁当前姿态 → 卸力），不能让求解器卡住主循环。
- **MPC（模型预测控制）**：输入当前状态 + 未来 N 步参考 + 简化模型；输出未来 N 步的地面反力/足端落点/接触序列。滚动优化，只执行第一步。周期：20–100 Hz（受 QP 求解时间限制）。数据来源：状态估计、步态时序、地形估计。真机风险：预测模型的摩擦/地形假设错了会"算得很漂亮、走起来打滑"，所以 MPC 输出必须再经软限位与斜率限制。
- **强化学习（RL）运控基础**：输入观测（IMU 姿态与角速度、关节角/角速度、上一帧动作、命令速度、地形感知特征），输出动作（通常是关节目标位置偏移或力矩）。训练在仿真里做（域随机化：质量、摩擦、延迟、传感器噪声），策略部署为单次前向推理（0.5–2 ms 量级）。真机风险最高：① 观测与训练分布不一致（真实 IMU 噪声水平与仿真不同）；② 动作无物理含义，没有解析的限位保证 —— **必须在输出层加硬限位与斜率限制**，并保证任何时刻能一键切回站立控制器（安全状态机见下）。

### 4. 控制层级与状态机

- **位置控制**：输入 `q_des`，电机内部做 P（+前馈）闭环；输出实际关节角。优点：行为可预测、不易失稳，是站立与低速行走的默认选择。风险：位置环硬顶地面时会产生大力矩（撞到障碍或脚卡住时电流飙升），必须配合力矩上限。
- **速度控制**：输入 `q̇_des`，适合轮足或需要柔性跟随的关节；风险：外力推动下不会回位，站立时容易"软腿"。
- **力矩控制**：输入 `τ_des`（常写成 `τ = Kp(q_des−q) + Kd(q̇_des−q̇) + G(q)`，即 PD + 重力补偿 + 可选前馈）。这是 WBC/MPC/RL 的输出接口，柔顺、能吸收冲击；风险：参数错一个符号就是"全速撞限位"，因此**首次上电必须用极小 Kp 和力矩上限，且手边能断电**。
- **状态机（state machine）**：至少 `INIT → CALIB → DAMPING（卸力）→ STAND_UP → STAND → WALK → SIT_DOWN → ESTOP → FAULT`。规则：任何时刻只有一个状态写电机；转移必须满足前置条件（如进入 WALK 前要求姿态误差 < 5°、足端接触有效、通信心跳正常）；`ESTOP`/`FAULT` 优先级最高且只能人工复位。周期：与主控同步（100–500 Hz 判定足够）。
- **轨迹与关节插值**：关节空间常用五次多项式（位置/速度/加速度连续）或 S 曲线加加速度限制；不要在关节空间做线性插值后直接给位置环 —— 速度阶跃会激发机械共振。默认限制：关节速度 ≤ 标称最大转速的 30%（首轮调试），加加速度限制取"能在 0.3 s 内从静止到 30% 速度"。数据来源：规划层；输出：逐周期的 `q_des, q̇_des, q̈_des`。
- **足端轨迹**：输入 步长、抬腿高度、站立相占比、步态周期；输出 足端在机体系的期望位置序列。摆动相常用摆线或贝塞尔：起点/终点速度为零、中间抬高 3–8 cm（首轮建议 3 cm）。落足点由 Raibert 式启发式给出：`p_land = p_hip + v·T_stance/2`。数据来源：状态估计的机体速度、步态相位。**足端轨迹永远是"期望"**，真机上要限制足端速度与加速度，否则触地瞬间冲击力会打坏减速器。
- **步态（gait）**：walk（三足支撑、最稳、默认首选手工步态）→ trot（对角小跑、动态平衡、需要状态估计与力控配合）→ pace/bound（更激进，真机风险高，最后再碰）。输入：期望速度与转向率；输出：每条腿的相位与站立/摆动标志。周期：步态周期 0.4–0.8 s（walk 首轮建议 ≥ 0.8 s）。
- **身体姿态控制**：输入 期望躯干高度、roll/pitch、重心偏移；输出 各腿 IK 目标 + 躯干位姿补偿。作用：上坡下坡保持水平、单腿抬起时把重心移到支撑多边形内。数据来源：IMU 姿态 + 足端接触。这条链路必须先"静止站立"调通再叠加步态。
- **状态估计（state estimation）**：IMU 给姿态与角速度（100–1000 Hz）；编码器给关节角与关节速度（1 kHz）；足端接触给"哪只脚在地上"（力传感器阈值或关节力矩估计）；力传感器给地面反力与打滑线索。融合后输出机体姿态、速度、高度、足端位置在世界系的估计。最小可用方案：IMU 姿态 + 腿部运动学里程计（足端不动时把机体位移反推出来）+ 互补滤波；进阶用 EKF/因子图。真机风险：估计漂移与"打滑误判"会让步态时序整体错位，因此**接触判定要用连续 2–3 个周期的确认 + 超时回退**。

### 5. 分级安全门禁（硬性，未过闸不得进入下一级）

总原则：**每级都必须先确认"停下来"是可靠的，再确认"动起来"是对的。** 任何一级不通过就停在该级修，不允许"先上真机试试"。上一级的日志与参数必须留档，否则视为未过闸。

| 级别 | 目标 | 进入条件 | 通过判据 |
|---|---|---|---|
| G0 仿真 | 算法与限位逻辑正确 | 无（纯软件） | 仿真连续运行 ≥ 30 min 无 NaN/发散；限位触发有日志；跌倒可复现 |
| G1 低速低力矩 | 单关节能安全动、能安全停 | G0 过；机械已固定；急停可触达 | 单手可随时断电；力矩上限压到最小可用值；限位与 Watchdog 各人为触发 1 次有效 |
| G2 单腿悬空 | 单腿 IK/FK 与极性正确 | G1 过；该腿离地悬挂/吊架 | 期望足端位置与实测足端位置误差 < 1 cm；拔网线后 0.5 s 内卸力 |
| G3 站立平衡 | 四腿同时支撑不摔 | G2 过；有吊架/安全绳 + 一人守急停 | 站立 10 min 姿态误差 < 3°；外部轻推能恢复；解除使能能软塌而非砸下 |
| G4 整机低速 | walk 步态能走且能停 | G3 过；空旷软地面；现场 ≥ 2 人 | 0.1 m/s 直线 ±5 m，偏移 < 20 cm；收到急停 ≤ 0.5 s 内进入 DAMPING |
| G5 常规运行 | 接近产品指标 | G4 过；参数与日志归档 | 连续运行 30 min 无故障；通信中断、传感器掉线、低电量三类故障演练各 1 次通过 |

每级必须逐项确认的安全清单（逐条打勾，缺项即不过闸）：

1. **急停（E-stop）**：硬件断电通道 + 软件 `ESTOP` 双通道；软件急停从收到指令到卸力的延迟 ≤ 0.5 s（G1/G2 可用示波器或日志时间戳测）。急停后必须**只能人工显式复位**，不要自动恢复。
2. **Watchdog**：主控每周期喂狗；控制循环超时（默认 20 ms，即 50 Hz 的兜底）→ 立即进入 DAMPING 并停机。喂狗点必须放在"控制量已算完并已下发"之后，否则会掩盖卡死。
3. **软限位**：角度（每个关节相对零位的上下限，留 ≥ 5° 机械余量）、速度（首轮 ≤ 标称的 30%）、力矩/电流（首轮 ≤ 标称的 20–30%）、足端工作空间（球/盒形边界，超出时截断到边界并报警，不要直接报错停机）。全部在**指令生成侧**和**下发侧**各校验一次。
4. **通信超时**：与电机/下位机的总线周期 ≥ 200 Hz；连续 3 个周期无应答即判失联；与上位机/APP 的心跳 10 Hz、超时 0.5 s。失联 → 停止接收新指令、进入 DAMPING。
5. **失联保护**：有线断开、Wi-Fi/无线丢包、上位机进程崩溃、SDK 连接断开，四种都要演练一遍；行为统一为"机器人自己进入安全姿态"，而不是"停在原地等指令"。
6. **跌倒与异常姿态保护**：IMU 判定 |roll| 或 |pitch| > 45° 持续 0.2 s → 判跌倒 → 立即卸力并锁存故障码。同时监控：关节角速度超限、单腿力矩持续异常、机身高度突变。
7. **日志与回滚**：每周期记录 `t, q, q̇, τ, state, flags`（环形缓冲 + 触发式全量落盘），任何一次异常都能离线复现；参数改动必须可一键回滚到上一版（版本化配置文件，不要手改数值不留痕）。

## 最小可运行示例

单腿逆运动学（纯数值，只依赖 Python 标准库，不需要任何 SDK/ROS）。它自带工作空间与关节限位校验——**这三道校验就是软限位的最小形态**。

```python
# leg_ik.py —— python3.8+，无第三方依赖
import math

L1, L2 = 0.29, 0.30          # 大腿/小腿长度(m)：待核实，必须用你的 URDF 实测值替换
LIMITS = {                    # (min, max) 弧度：先用保守值，真机标定后收紧
    "hip": (-0.60, 0.60),
    "thigh": (0.0, 1.75),
    "shin": (-2.62, -0.35),
}

def _check(name, q):
    lo, hi = LIMITS[name]
    if not (lo <= q <= hi):
        raise ValueError(f"{name} 超软限位: {q:.3f} rad 不在 [{lo}, {hi}]")
    return q

def leg_ik(x, z):
    """输入：足端在髋关节坐标系的 (x 前, z 下为正) 目标，单位 m。
    输出：髋偏航/大腿/小腿三个关节角(rad)，机体/几何约定：大腿向前、膝盖向前。"""
    r2 = x * x + z * z
    if not (0.05 <= r2 <= (L1 + L2) ** 2 * 0.98):        # 工作空间边界，留 2% 余量
        raise ValueError(f"目标超出工作空间: r={math.sqrt(r2):.3f} m")
    q1 = math.atan2(x, z)                                # 髋在矢状面内的摆角
    d = math.sqrt(r2)
    c3 = (d * d - L1 * L1 - L2 * L2) / (2 * L1 * L2)     # 余弦定理
    q3 = -math.acos(max(-1.0, min(1.0, c3)))             # 膝盖向前弯 → 负角
    q2 = math.atan2(x, z) - math.atan2(L2 * math.sin(q3), L1 + L2 * math.cos(q3))
    return _check("hip", q1), _check("thigh", q2), _check("shin", q3)

def leg_fk(q1, q2, q3):
    """正运动学，用于自检：IK 解回代必须与目标一致。"""
    d = math.hypot(L1 + L2 * math.cos(q2 + q3), L2 * math.sin(q2 + q3))
    a = q2 + math.atan2(L2 * math.sin(q2 + q3), L1 + L2 * math.cos(q2 + q3))
    return d * math.sin(a), d * math.cos(a)

if __name__ == "__main__":
    for target in [(0.00, -0.30), (0.10, -0.25), (0.15, -0.20)]:
        q = leg_ik(*target)
        got = leg_fk(*q)
        err = math.dist(target, got)
        print(f"target={target} q(deg)=[{', '.join(f'{math.degrees(v):7.2f}' for v in q)}] "
              f"fk_err={err * 1000:.3f} mm")
        assert err < 1e-9, "IK/FK 不自洽"
    try:
        leg_ik(0.40, -0.60)          # 故意超出工作空间
    except ValueError as e:
        print("限位生效:", e)
```

验收方式：`python leg_ik.py` 打印三组角度的 `fk_err` 应 < 0.001 mm，并最后打印一行"限位生效"。误差改成毫米级都算不合格——那说明公式或约定抄错了。

## 工程实现要点

- **目录分层（每层一个可独立测试的模块）**：
  ```
  locomotion/
    frames.py        # 坐标系与姿态转换：四元数/旋转矩阵/欧拉角，唯一转换入口
    robot_model.py   # 从 URDF 读取连杆长度、质量、关节限位；禁止在算法里硬编码长度
    kinematics.py    # FK / IK / Jacobian（可纯函数，无状态，最易写单测）
    gait.py          # 相位、步态时序、Raibert 落足点 → 期望足端轨迹
    body_control.py  # 躯干位姿、重心、地形适应 → 各腿足端目标
    state_estimation.py  # IMU + 编码器 + 接触融合
    controllers/     # joint_pd.py / cartesian_impedance.py / wbc.py / mpc.py / rl_policy.py
    safety/          # limits.py / watchdog.py / state_machine.py / estop.py  ← 独立模块，被所有层调用
    io/              # bus_adapter.py（CAN/EtherCAT/串口/仿真），上层只依赖抽象接口
    config/          # robot.yaml(几何与限位) + gains_g1.yaml/g3.yaml/g4.yaml（按门禁级别分档）
  ```
- **分层解耦**：算法层只处理 `q / q̇ / τ / 足端位姿`，**不 import 任何厂家 SDK**；SDK 只出现在 `io/bus_adapter.py` 里。这样换机器人、上仿真、跑回放都不改算法。仿真与真机用同一个 `bus_adapter` 接口，只切换实现（这与项目里 `ControlService → Mock/SDK/ROS2` 的解耦思路完全一致）。
- **配置与安全值外置**：限位、增益、周期、超时全部放配置文件并带单位（`rad`、`deg/s`、`N·m`），加载时校验范围；禁止把"临时调大的限位"提交进仓库。每档门禁一套增益文件（`gains_g1.yaml` 力矩上限最小，`gains_g4.yaml` 逐步放开）。
- **时间处理**：所有控制量按**时间戳**推进，不用"第几帧"。主循环用 `time.perf_counter()` 计算 `dt`，`dt` 超出 [0.5×, 2×] 标称周期就丢帧并计数，计数超阈值进 FAULT。
- **失败路径**：每个模块都要回答"输入非法时怎么办"。框架：传感器数据超时 → 用上一帧并标记 `stale`；IK 不可解 → 保持上一组关节角并降速，绝不用 NaN 下发；QP 无解 → 降级到 PD 站立；策略推理超时 → 切站立控制器。**任何情况下都不允许把 NaN/Inf 或超限值写到总线上**（在 io 层做最后一道断言）。
- **学习写法 vs 生产写法**：① 初学者常把 `q1, q2, q3` 硬编码长度、把限位写在 `if` 里、把控制循环写成 `while True: time.sleep(0.001)`；② 企业写法是几何参数全部从 URDF/标定文件读、限位集中在 `safety/limits.py`、循环用固定周期的实时调度并统计抖动（jitter）与丢帧；③ 差别原因是可移植性与可追溯性——真机换一批零件或换一台机器，硬编码值会让"上次能跑"变成"这次摔倒"，而集中限位能在一次评审里审完所有安全边界。
- **与上层链路对接**：APP/上位机 → MQTT/ROS 2 速度指令 → 安全校验（速度/角速度上限、指令有效期）→ 状态机 → 步态与 WBC → 关节指令 → 总线。指令必须带 `request_id` 与 `timestamp`，超过有效期（建议 0.5 s）的命令直接丢弃并回 `TIMEOUT`；离线时明确返回 `OFFLINE`，**不得假装控制成功**。

## 常见坑与验收标准

坑：

1. 用欧拉角做姿态积分或插值 → 万向锁与跳变。**修法**：内部一律四元数，积分后单位化。
2. 关节零位/正负号/单位（rad vs deg）不一致 → 一上电就往限位冲。**修法**：`frames.py` 与 URDF 的 axis 逐一核对，先写一个"给 5° 步进、观察实际转向"的标定脚本，输出转成 CSV 存档。
3. FK 与 IK 约定不统一（膝盖朝前/朝后）→ 站立时腿呈"跪姿"。**修法**：永远用 IK→FK 回代自检（见上面的 `assert`）。
4. 漏掉重力补偿 → PD 位置控制下腿"软塌"，需靠很大 Kp 硬顶，一碰就抖。**修法**：加 `G(q)` 前馈，Kp 就可以小很多。
5. 接触判定用单帧阈值 → 抖动误判，步态时序错乱。**修法**：连续 2–3 周期确认 + 最小接触时间。
6. 控制周期抖动没测 → 平时正常，一抓日志（或一开可视化）就发散。**修法**：长期监控周期 P99 抖动，把日志写成环形缓冲、异步落盘。
7. 力矩上限只在软件算完限一次 → 总线层仍可能收到超限值。**修法**：下发前二次钳位并断言。
8. 只做仿真不做逐步放开 → 参数在仿真里"最优"，真机第一脚就摔。**修法**：门禁逐级过，每级只改一个量（先降速度，再放增益）。
9. 强化学习策略直接上真机 → 观测分布不匹配导致乱动。**修法**：先测推理延迟与观测范围，输出加硬限位，随时能切回站立控制器。
10. 忘记"停下"比"动起来"重要 → 先调行走、急停没测。**修法**：每级门禁第一件事是测急停与 Watchdog。

验收标准（能全部做到才算掌握，逐条给自己打勾）：

- 能画清 `world/body/joint` 三个坐标系和 TF 链，并指出一次"坐标系搞混"会导致的实际现象。
- 能从 URDF 读出关节轴、限位、连杆长度，并说明哪几个值会直接影响 IK 结果。
- 手写单腿 IK 并通过 FK 回代自检（误差 < 0.001 mm），能解释余弦定理中 `q3` 取负号的几何含义。
- 能写出 PD + 重力补偿的关节力矩指令形式，并说清 Kp/Kd 变大变小各自的现象。
- 能解释 Jacobian 的两种用途（速度映射、力矩映射）与奇异点为什么会危险。
- 能说明控制周期为什么内层快（500 Hz–1 kHz）、外层慢（50–200 Hz），并会测量循环抖动的 P99。
- 能为一台机器人写出完整的软限位表（角度/速度/力矩）并说明每个数字的依据来源。
- 能默写六级门禁的进入条件与通过判据，并说明"未过闸不得进入下一级"的理由。
- 能现场演示三类故障保护：拔网线、推倒（或强制置姿态角超阈值）、触发急停，各观察 1 次正确行为。
- 能说出 RL 策略上真机前必须做的三件事（观测分布核对、输出硬限位、可切换回站立控制器）。

## 学习路径

前置知识：线性代数（矩阵乘法、特征值概念）、微积分（导数/积分、优化直觉）、Python 数值编程（NumPy）、基础力学（力矩 = 力 × 力臂、牛顿-欧拉思想）、以及 06 文件的 ROS 2 与 TF2、07 文件的通信与 Watchdog。

顺序与里程碑（每个里程碑都有一个可见产出）：

1. **坐标系与姿态**（能写四元数 ↔ 欧拉角 ↔ 旋转矩阵互转并通过往返测试）→ 产出 `frames.py` + 单测。
2. **单腿 FK/IK**（本文件的示例改写为自己机器人的参数）→ 产出 IK/FK 回代自检脚本。
3. **仿真环境里的位置控制站立**（MuJoCo/Gazebo/Isaac 一类，具体选型 `待核实` 你的技术栈）→ 产出 G0 通过记录。
4. **Jacobian 与笛卡尔阻抗控制**（能拖动机体而不失稳）→ 产出 G2 单腿悬空记录。
5. **状态估计与接触检测**（能画出机体速度估计与实际对比曲线）→ 产出 G3 站立平衡记录。
6. **步态与足端轨迹**（先 walk，后 trot）→ 产出 G4 整机低速行走记录。
7. **WBC / MPC / RL 入门**（先读通一个开源四足运控工程的结构与数据流，再动手改一处小功能）→ 产出 G5 常规运行记录与一份参数归档说明。

每完成一级，把当次记录（参数、日志路径、异常现象、结论）写进档案目录的 `notes/` 与 `progress.md`，门禁状态只认证据。
